# 用 Claude Code（harness）实现"100% 代码"视频

本片没有使用任何图片、视频素材或音频采样。每一帧画面都由浏览器中的 Canvas 2D 与 WebGL 着色器计算得出，每一个声音都由 Python 数学函数合成，最后用 ffmpeg 合成成片。Claude Code 在其中同时承担编剧、事实核查、美术、程序和混音的工作：写代码，渲染静帧，自己"看"静帧，再修改代码，循环迭代。

## 一、制作流程（实际执行的顺序）

| 阶段 | 做法 | 产出 |
|---|---|---|
| 1. 研究 | 并行子代理：活动规则与爆款规律、6 个开源"代码做视频"仓库的方法、参考片逐帧与频谱拆解 | `docs/01`、`docs/02` |
| 2. 事实核查 | 工作流：三组研究员分组核查，再由质疑者逐条尝试推翻措辞 | `docs/05`、`docs/07` |
| 3. 字幕 | 唯一数据源 `script/subtitles.py`，脚本检查每行宽度（≤18 字），并由四个视角审校：古代史实、近现代史实、中文编辑、抖音观众 | `docs/06_字幕稿.md`、`engine/data/script.js` |
| 4. 分镜 | 每个场景一份制作说明：风格卡、标题时刻、每张字幕卡对应的画面节拍、入场转场、音效提示点 | `docs/08_制作分镜_briefs.md` |
| 5. 场景制作 | 两条并行工作流，每个场景两个代理：制作者实现并自查；独立"美术总监"复查后直接修改 | `engine/scenes/*.js`（14 个） |
| 6. 集成检查 | 逐个检查 13 处篇章转场；逐章渲染检查图；修复引擎级问题 | — |
| 7. 声音 | `audio/score.py` 读取时间轴与各场景的音效提示点，合成配乐、音效与频谱彩蛋 | `out/audio/` |
| 8. 成片 | `build.sh`：并行逐帧渲染 → 拼接 → 合成音轨 → 响度标准化 → 成片、仅音效版、封面 | `out/` |

## 二、引擎结构

```
engine/
  index.html        时间轴与渲染入口：renderFrame(n) / renderTime(t)
  scenes.js         场景清单；?ids=a,b 只加载指定场景，单个场景出错不影响其他场景
  lib.js            数学、种子随机数、噪声、WebGL 着色器运行器（GL.run / GL.bake）、逐字显现的文字排版
  stage.js          统一版式：opener()（每章开头约 3 秒的标题时刻）与 subs()（字幕）；不设任何角落标签
  transitions.js    通用转场：墨晕、燃烧、龟裂、像素、扫描、故障、百叶、翻页、光圈、推镜等
  scenes/<id>.js    每章一个文件 = 一张风格卡；自带入场转场（TRANS.<id>_xxx）与音效提示点 cues
  data/script.js    由字幕源文件生成的定稿文字与时间
  data/spectro.js   由最终混音计算出的频谱，供结尾场景显示
render/
  render.js         Playwright 驱动无头 Chromium（SwiftShader 软件 WebGL）：stills / range / info
  parallel.sh       多进程分段渲染，可断点续渲，最后无损拼接
  qa_sheet.py       单个场景的检查图：标题时刻与每张字幕卡的中点
audio/
  dsp.py            乐器与音效：拨弦、钟、笛、管风琴、人声、铜管、方波、合成铺底、火焰、骨裂、冲孔、拨号音……
  score.py          总谱：每章一套乐器与调式，"我在这里"四音动机在每个时代重新配器；按 cues 触发音效；频谱写字
```

## 三、确定性渲染的规则

1. 每一帧只是时间 t 的函数：不用 `requestAnimationFrame`、定时器、CSS 动画或 `Math.random()`，随机数全部来自固定种子。因此任意一帧都可以单独重渲，多个进程可以并行渲染不同区间。
2. 所有字体使用本地文件，在画第一帧之前全部加载。
3. 2D Canvas 固定在 CPU 上（`--disable-accelerated-2d-canvas`）。
4. 静态纹理（岩石、泥板、纸莎草、青铜锈、宣纸、织物等）在场景初始化时烘焙一次，之后每帧只做合成。
5. 复查代理对每个场景都做过"同一时刻渲染两次、逐字节比较"的检查。

## 四、多代理分工（Claude Code 工作流）

- 每个场景由两个代理先后处理。**制作者**阅读引擎说明与分镜，写出场景文件，渲染静帧并读图自查，反复修改。**美术总监**不看制作者的结论，自己重新渲染，按清单审查：角落是否有小字、字幕是否清晰、风格是否地道、每张字幕卡是否有对应画面、转场、速度、确定性、文字是否越出定稿；发现问题直接修改。
- 两条工作流并行，同时有四个代理在工作。
- 代理只能修改自己的场景文件；共享引擎由主线程维护。复查中发现的引擎级问题（例如逐字排版的对齐、标题时刻计数时的空隙）由主线程统一修复。

## 五、声音

- 96 BPM，每章时长对齐到半小节，转场落在节拍上。
- 每章一套乐器与调式，例如安第斯笛与拨弦、竖琴与叉铃、编钟与埙、古琴、古筝、琵琶与箫、管风琴与鲁特琴、音乐盒、颤音琴、芯片音乐、大乐队铜管、极简电子，结尾回到钢琴。
- 场景文件中的 cues 触发对应音效：结绳拉紧、压泥、火焰、骨裂、竹片、滴水、刻刀、陶字、压印机、冲孔、制表机铃声、走带、软驱寻道、盘片启动、风扇……
- 结尾约 4.5 秒的音轨中，以 4–10 kHz 的频带写出"我在这里"四个字：把文字图像当作时频矩阵，用逆短时傅里叶变换合成，然后计算最终混音的频谱，交给结尾场景显示。
- 母带：约 −14 LUFS，限幅 −1.5 dB；另出一版只有音效的音轨（−20 LUFS），便于在抖音曲库选曲。

## 六、常用命令

```bash
python3 script/subtitles.py                     # 检查字幕宽度并生成 engine/data/script.js
NODE_PATH=$(npm root -g) node render/render.js info                       # 时间轴
NODE_PATH=$(npm root -g) node render/render.js stills out/s 1.8,6.0 clay  # 单个场景的静帧
python3 render/qa_sheet.py clay out/qa                                    # 单个场景的检查图
bash build.sh audio                              # 只做声音
bash build.sh                                    # 全片
```
